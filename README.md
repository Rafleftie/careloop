# CareLoop

Closes the gap between an abnormal cervical screening result and actual treatment.
Built for the Future Health Digital Innovation Challenge, track: Closing the Screening-to-Care Loop.

**Live demo:** https://YOUR-APP-NAME.onrender.com  (replace after deploying)
The free host sleeps when idle, so the first load can take about a minute.
Start at `/patients`, open the top patient, then click "Open patient app view".

> All patients, scores and messages are SYNTHETIC. No real patient data is used. SMS sending is simulated.

## What it does
- Predicts which referred women are likely to miss their follow-up visit, and shows the top 3 reasons in plain words.
- Recommends a next action for each patient: SMS reminder, nurse call, transport support or CHW home visit.
- Patient side (mobile web, English and Kiswahili): care journey, reschedule with a required reason, privacy choices, messages.
- Consent-aware simulated SMS outbox that escalates patients who ignore 2 reminders to their community health worker.
- A high score means more support for the patient, never lower priority for care.

## Scope
- Use case: cervical cancer screening follow-up (VIA / HPV / Pap smear), one clinic, Kiambu County, Kenya
- Cascade: Screened -> Referred -> Hospital visit -> Treatment started
- Data: SYNTHETIC ONLY, generated by `generate_data.py`

## Run it locally (just the app)
```
python -m venv .venv
.venv\Scripts\activate           # Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
python -m uvicorn app.main:app --reload    # open http://127.0.0.1:8000
```
The database with scores is included, so nothing else is needed.

## Rebuild the data and the model (optional)
```
pip install -r requirements-train.txt
python generate_data.py          # 5,000 synthetic patients -> data/careloop.db
python model/train.py            # trains and benchmarks the risk model, writes risk scores
python app/seed_worklist.py      # 48 demo patients with upcoming visits
```

## Deploy for free (Render)
1. Push this repo to GitHub.
2. On render.com sign in with GitHub, choose New > Web Service and pick this repo.
3. Language: Python 3. Build command: `pip install -r requirements.txt`.
   Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`. Instance type: Free.
4. Deploy. The Python version is pinned to 3.12 by `.python-version`. `render.yaml` holds the same settings.

Free-tier notes: the service sleeps after 15 minutes without traffic and takes about a minute to wake.
Its disk is not persistent, so the demo resets to the committed database on every restart. That also
makes "restart the service" the way to reset the demo.

## Layout
- `generate_data.py` synthetic screening -> treatment cascade
- `model/train.py` logistic regression vs gradient boosting, calibration, fairness check, top-3 reasons per patient
- `app/main.py` FastAPI backend
  - Coordinator pages: `/dashboard`, `/patients`, `/patients/{id}`, `/outbox`
  - Patient app pages (mobile, EN/SW via `?lang=sw`): `/patient/{id}`, `/patient/{id}/reschedule`, `/patient/{id}/consent`, `/patient/{id}/messages`
  - API: `/api/patients`, `/api/patients/{id}`, `/api/cascade`, `POST /api/patients/{id}/actions`, `POST /api/patient/{id}/reschedule|consent|confirm`, `POST /api/outbox/send-due|escalate`
- `app/i18n.py` patient-facing strings (Kiswahili is a draft that needs native review)
- `app/templates/` pages built from the Stitch designs, `app/static/tailwind.config.js` design tokens

## Model results (synthetic data, 5-fold cross-validation)
AUC 0.70. The top 20% flagged catch 35% of missed visits (random targeting: 20%).
These numbers show the pipeline works, not real-world accuracy.

Known limitation found by the fairness audit: patients who live close to the clinic and still miss
visits are caught far less often (11% of missed visits caught under 5 km, 74% over 10 km).
Everyone gets the standard reminders; the score only decides who gets extra support.

## Demo story (about 3 minutes)
1. Dashboard: 442 of 1,244 referred patients never reached the visit.
2. Patients: the model ranks upcoming visits and says why. Open the top patient.
3. Click "Open patient app view": the patient sees a calm care journey, then changes the visit and must say why (e.g. "Feeling anxious").
4. Back in the coordinator view: the visit date changed, the reason shows in the timeline, and the recommended action became "Nurse phone call".
5. Outbox: send due reminders (respecting SMS consent), then escalate patients who ignored 2 reminders to their CHW.

## Limits of this prototype
- No login or encryption: it is a demo on synthetic data. A pilot would need role-based access, TLS, encryption at rest and audit logs.
- SMS is simulated. A pilot would connect a real gateway.
- Not a diagnostic tool. It supports scheduling and outreach only.
